# Cost, Modes and Evidence: Full RD-08 Optimizer

> **Document**: 03-03-cost-modes-and-evidence.md
> **Parent**: [Index](00-index.md)

## Overview

Every candidate is compared only after complete B/R/T accounting. The v1
evidence schema is reused; the optimizer adds exact/range/symbolic T terms and
debug optimization records where the schema already supports them. No schema
version change or post-publication rewrite is introduced.

## Cost Vector

| Component | Definition |
|---|---|
| `B` | Final loadable compiler-generated bytes: code, initialized data, assets, helpers, tables, padding, branch repair, startup and packaging payload. BSS is excluded from loaded bytes. |
| `R` | Ordered resources: `zeroPage`, `residentRam`, `hardwareStack`, `scratch`, then declared profile resources. |
| `T` | Comparable semantic path cycles: entry-to-return and any path class a rule actually changes. Exact, range or symbolic terms are allowed; unknown is honest. |

B and R come from the final layout/certificate. T comes from machine instruction
and terminator costs under final block placement. No guessed frequency is
allowed.

## Selection Rules

| Mode | Order |
|---|---|
| `none` | Direct baseline only; no candidate enumeration |
| `size` | B → R → T |
| `speed` | T (worst-to-best vector) → R → B |
| `balanced` | No candidate unless weakly no worse than baseline and every feasible competitor on B, T and R, with at least one strict improvement; otherwise retain the feasible baseline |

Exact complete ties use the lexicographically smallest stable candidate ID.
Unknown or incomparable terms are never zero, a win or a stable-ID tie. A mode
failure identifies the exact deficit/tradeoff; it never becomes a source
restriction.

### Cost API

```ts
/** Exact, bounded, symbolic or honestly unavailable cycle term. */
export type OptimizationCycleMeasurement =
  | { readonly kind: "exact"; readonly value: number }
  | { readonly kind: "range"; readonly minimum: number; readonly maximum: number }
  | {
      readonly kind: "symbolic";
      readonly expression: string;
      readonly variables: readonly { readonly name: string; readonly minimum: number; readonly maximum: number }[];
    }
  | { readonly kind: "unknown" };

/** Complete B/R/T vector used by all modes. */
export interface OptimizationCostVector {
  readonly programBytes: number;
  readonly pathCycles: readonly {
    readonly pathId: string;
    readonly cycles: OptimizationCycleMeasurement;
  }[];
  readonly resources: readonly {
    readonly kind: "standard";
    readonly id: "zeroPage" | "residentRam" | "hardwareStack" | "scratch";
    readonly value: number;
  }[];
}

/** One stable candidate identity and its closed vector. */
export interface OptimizationCandidate {
  readonly id: string;
  readonly cost: OptimizationCostVector;
}

/** One comparison result; no hidden weights or guessed frequency. */
export type CostComparison =
  | { readonly kind: "less" }
  | { readonly kind: "equal" }
  | { readonly kind: "greater" }
  | { readonly kind: "incomparable"; readonly components: readonly string[] };

/** Compare two closed vectors under one mode's exact ordering. */
export function compareOptimizationCosts(
  mode: "size" | "speed" | "balanced",
  left: OptimizationCostVector,
  right: OptimizationCostVector,
): CostComparison;

/** Select a candidate, or report that no balanced candidate dominates. */
export type OptimizationSelection =
  | {
      readonly kind: "selected";
      readonly candidateId: string;
      readonly tieBreak: "none" | "stableId";
      readonly incomparableComponents: readonly string[];
    }
  | { readonly kind: "none"; readonly incomparableComponents: readonly string[] };

export function selectOptimizationCandidate(
  mode: "size" | "speed" | "balanced",
  baseline: OptimizationCandidate,
  candidates: readonly OptimizationCandidate[],
): OptimizationSelection;
```

## Mode Surface

RD-08 requires exactly `none`, `balanced`, `speed`, `size`; `balanced` is the
production default. The implementation sequence is:

1. Keep `none` and current explicit `size` behavior.
2. Add internal B/R/T selection for `size` and qualify saved/acquisition.
3. Add `balanced`/`speed` selection only after the size pipeline is stable.
4. Wire the public build/CLI acceptance for all four modes only in the final mode
   phase; `size` remains marked experimental until its limits pass.

The existing manifest default is not changed silently into an unqualified mode;
the mode phase owns that public behavior and its tests.

## Evidence

The existing `.costs.json` decision record is reused:

- stable candidate IDs include source hash, mode, rule-set identity and layout;
- rejected candidates carry exact hard reasons and no vector;
- selected candidates carry the final complete B/R/T vector equal to totals;
- baseline may be feasible or rejected; a rejected baseline has no invented
  before-vector or zero delta;
- exact ties and incomparable components are explicit.

`.debug.json.optimizations` is populated only for actual applied rules. It
records stable rule/candidate identities, source sites, rematerialization or
optimized-away status, and never invents an unavailable location. `.memory.json`
remains the physical source of truth.

## Publication

Only the selected generation is serialized and assembled. A rule/cost/certificate
failure keeps the last-good generation and publishes no partial attempt. ACME
reconciliation and cross-artifact hashes must match the selected candidate after
final layout; a mismatch is a failure, not a fallback to an earlier attempt.

## Error Handling

| Error Case | Handling | AR Ref |
|---|---|---|
| Decisive T unknown | Candidate cannot win or tie; keep baseline/other proof | AR-010 |
| B/R/T components incomparable | Mark incomparable; balanced retains baseline | AR-010 |
| Selected vector disagrees with totals | Terminal evidence failure; no publication | AR-010 |
| Rejected baseline has a fabricated vector | Evidence validation failure | AR-002 |
| Public mode is not qualified | Do not expose a release claim; keep experimental | AR-002, AR-004 |
| Native claim exceeds VICE evidence | Report VICE-verified / hardware-unverified | AR-015 |

## Testing Requirements

- Exact/range/symbolic B/R/T composition and unknown handling.
- Size selection ordering and stable-ID tie.
- Balanced no-regression Pareto rule.
- Speed vector ordering.
- Rejected-baseline round-trip and invalid records.
- Deterministic build/evidence repetition.
- Final ACME/PRG/memory/cost/debug hash reconciliation.
