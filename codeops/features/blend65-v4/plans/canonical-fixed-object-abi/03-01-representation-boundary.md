# Canonical returned-object representation boundary

> **CodeOps Artifact Schema**: 1
> **Design authority**: AR-P6/7/9; C-1–C-11

## 1. Restricted producer

Use existing closed-object/returned-local queries for the same immutable checked
program. Seed eligibility only from a selected result with a matching
`returnedLocalDestinations` entry, complete unique whole-object caller origin
and early-publication proof. Only parameter origins resolving to those exact
eligible roots join the group. Equality includes owner, binding, complete type
and whole-object path, never names or numeric addresses.

Build/seal the restricted map at the existing selection derivation owner. Never
filter a sealed Closed map or trust a program-level flag. The optimized Closed
derivation remains unchanged.

## 2. Object-only handoff

Reuse `MachineSourceFacts`/function storage packets with an explicit internal
canonical-object scope distinct from Closed. Keep Direct/Original choices,
default startup, absent `optimizationFacts`, and no complement/other optimizer
admissions. Validate the complete map against source/facts and the restricted
derivation before consumption. No public option/schema or policy registry.

### Metadata is not transformation authority

Both real generic and restricted constructions need authentic producer-collected
operation/block associations. Use an explicit internal metadata-only scope in
the approved machine types/service wiring. Do not infer it from absent optimizer
facts or reconstruct associations from source spans afterward.

At `machine/lower-function.ts`'s existing `ordinalBoundsForFunction` call,
metadata-only construction passes the query its prior conservative observer
authority while ordinary lowering still collects annotations. At the existing
`machine/lower.ts` folding and data-removal calls, retain the original
transformation guards. Audit every evidence-flag consumer. No stronger bounds,
fold, changed data/demand or startup may follow from metadata alone. Preserve
the old optimized evidence/transform behavior. The caller adaptation stays small
and explicit; if it cannot, reopen scope before touching `machine/lower-bounds.ts`.

## 3. Storage closure

Use existing allocation-independent declarations and projection; generic
provisional placement cannot pretend demand is already removed. Caller,
callee, place and result consumers share the sealed selection. Project only
explicitly replaced requests with no actual machine access. Keep backing,
staging, captures and helper requests still needed; close/bind the entire tuple.

Freshness does not make nested destinations identical. Different result roots,
mixed borrowers, escaped/indirect entries and unproved asynchronous access keep
generic representation. Add no pinning, heap, stack frame or dispatcher.

## 4. Service and final proof

Retain the real generic construction through existing canonical reference
closure. At that service owner, attempt only eligible object representation;
do not enumerate optimizer candidates or change optimized canonical references.
The existing `services/services.ts` hook and `machine/lower-aggregate.ts` direct
fixed-result/nested construction are the AR-P11-approved seams for this attempt.
The attempt cannot recurse into itself. Preserve startup-pressure retry and
all visibility/fallback duties.

Run existing storage/source/borrow/physical observers on real generic and
restricted constructions. Extend the explicit reference-form assumption for
certified canonical fixed backing; validate both forms rather than treating new
backing as empty or already proved. Successful bind is not publication permission.

At the AR-P9-approved `services/size-observer-effects.ts`, reuse existing
continuation checks for a bounded canonical-object unchanged-control admission.
Authenticate source-block membership and actual continuations in both final
layouts; preserve predicates, byte-counter initialization/update/comparison and
relevant value/flag dependencies. Differences are only independently certified
ABI substitutions and relocation, never arbitrary ignored instruction ranges.
Keep existing raw effective-byte order/count, pointer/dummy accesses, physical
envelopes, typed/async/lifetime and CPU/VIC obligations. Do not fabricate word-loop
facts or insert a bounds-map entry to bypass control admission. Missing
correspondence retains generic fallback; inconsistent evidence is an error.
No general control-flow engine, new loop representation, range analysis or
competing acceptance path is introduced.

An unproved eligibility/final obligation keeps generic output. Preserve genuine
terminal/internal failures; never catch arbitrary errors as harmless proof
misses. Publish no partial attempt. Result/debug/resource evidence is truthful;
public schemas and normal `none` evidence shape remain fixed.

## 5. Qualification seams

Use existing derivation/bundle/projection/final-consumer tests with no fake
successful receipt. Public tests use real package builds, ACME and VICE. Invalid
internal facts fail before emission or at final closure. No test-only mode.

Reconcile pointer removal, BASIC saves, complete code/data/padding/resources and
independent expert effects/costs. Pinned identities protect unrelated output.
A new owner or material mechanism outside AR-P6 reopens its scope gate.
