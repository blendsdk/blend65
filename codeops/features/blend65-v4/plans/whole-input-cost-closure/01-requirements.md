## Planned subset

Per AR-P1–AR-P4, this plan covers only the admitted consumers of RD-08
R8.2–R8.6, R8.9–R8.13, R8.16–R8.22, R8.25–R8.35, R8.38–R8.47,
R8.51–R8.54 and R8.58. These identifiers are partial ownership, not claims that
every technique in those requirements is implemented. RD-05 input contracts
and its existing keyboard ST-23 whole-output gate are unchanged except for the
explicit mode reconciliation recorded in AR-P4.

Full four-mode rollout, the wider optimization corpus, asset/delivery work,
general CFG/call transformations and final RD closeout remain with their original
owners. PF-003's approved fixed recipe admission, not every per-site mixture,
is the early qualified frontier. Its smaller scope must still meet every
original input outcome; no missing consumer is silently deferred.

## Plan-local acceptance

1. Every admitted rule in [03-02](03-02-machine-selection.md) has a complete
   source-to-selected-sequence proof and independent tests from [07](07-testing-strategy.md).
2. `none` follows the existing canonical path; explicit `size` uses only the
   qualified finite alternatives and complete selection in [03-03](03-03-closure-and-modes.md).
3. Both ordinary input programs satisfy the existing whole-output/resource
   bounds, every original behavior assertion and the original saved-simple
   timing bound. The AR-P4 estimates are not substitute acceptance limits.
4. The only existing specification-test amendments are the exact four-file
   AR-P4 exception. No frozen spec/expert or unrelated oracle amendment occurs.
5. Final register/constant/object recipes, actual homes and optimized source
   ranges fit the version-1 evidence contract with the exact approved PF-002
   feasible-baseline correction. No invented schema field, false availability
   or post-closure storage is accepted. A valid resource-rejected reference may
   not prevent an admitted feasible selected representation.
6. The one complete phase passes the inherited verification rule, independent
   correctness, semantics/DX, SFA/ABI, platform, output and host-performance
   reviews. Local expert meets are tracked under the existing authorized issue
   rule; a worse result blocks the checkpoint.

Security scope is the existing local compiler/CLI: validate mode values, keep
path/tool/publication protections, and publish only one validated generation.
Web authentication, CSRF, rate limiting, financial controls, encryption services,
containers and infrastructure are N/A; no such surface is introduced.

## Change boundaries

Production owners and new focused modules are enumerated in the three 03 docs.
Six public specification files belong under `test/rd08/`; the frontier/evidence
specification file is package-local so its existing artifact reader checks need
no new export or cross-package implementation import. New logic tests stay beside
their owners. Documentation changes are this plan, the exact keyboard mode
annotation, feature roadmap and `docs/platform-libraries.md`, plus only the
approved RD-03 feasible-ID paragraph. The existing costs-evidence validator is
an additional planned production owner, not a new subsystem. Package metadata,
dependencies, frozen authority, unrelated requirements, portfolio and existing
oracles outside AR-P4 are excluded. A newly required support family reopens the
complexity gate; it cannot be smuggled into a task as a fix.
