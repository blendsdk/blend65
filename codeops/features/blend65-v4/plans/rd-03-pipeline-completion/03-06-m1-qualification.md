# M1 Qualification: RD-03 Pipeline Completion

> **Document**: 03-06-m1-qualification.md
> **Parent**: [Index](00-index.md)

## Overview

Qualify one readable original-art Invaders-style project from source through a verified PRG and one
real VICE 3.10 run. The oracle, input trace and expert ACME twin are written before generated-code
acceptance and do not import compiler implementation code (AR-C1, AR-C11–AR-C13).

## Checked-In Fixture

`examples/m1/` contains exactly the user-facing qualification project:

```text
blend65.json
src/game.blend
assets/sprites.bin
qualification/sprite-recipe.ts
qualification/win-trace.json
qualification/oracle.ts
qualification/expert-m1.asm
qualification/README.md
```

The manifest selects `c64-pal-prg-kernal-6581`, `optimization: none`, both runtime checks `false`,
and the ordinary source/assets/output roots. `game.blend` owns the six-element enemy array,
collision functions, frame update and win/loss flow. It uses the exact named platform operations
from [Target and layout](03-03-target-assets-lowering-layout.md), not MMIO addresses, SFA homes,
VIC block arithmetic or ACME spelling (AR-C7, AR-C17).

The deterministic recipe produces the checked-in 512-byte raw file: eight distinguishable,
nonblank 64-byte records in the required order. Qualification records its SHA-256, generated bytes,
original-art statement and retention intent. The recipe is development evidence, not compiler input
or a private asset format. No SpritePad file or parser exists in this plan (AR-C1, AR-C6).

## Independent Behavior Oracle

`oracle.ts` is a small pure model derived only from the RD-03 behavior table. It takes a complete
fixed PAL-frame joystick sequence and emits expected per-frame state and observable device intent:

- player/enemy/projectile/explosion positions and state;
- one joystick sample and exact update ordering;
- rising-edge fire, collision winner and animation record;
- win/loss and border color;
- sprite enable/position/pointer/color writes in order; and
- terminal release/press and restoration/return markers.

It imports no compiler, frontend, emulator or generated artifact. The model freezes the complete
predetermined win trace before backend acceptance. A separate short input reaches loss without
VICE. Focused cases prove opposing directions, held fire, projectile limits, simultaneous-hit
lowest index and all explosion transitions (AR-C12, AR-C13).

## Expert ACME Twin

`expert-m1.asm` implements the same project behavior with the same raw bytes, profile, startup,
input trace, frame boundary, memory assumptions and BASIC return. It is hand-authored against the
pinned CPU/C64/ACME authorities and assembled separately with ACME 0.97. It is not generated,
copied from compiler output or reduced to a sprite demonstration (AR-C13).

The comparison records:

| Dimension | Evidence |
|---|---|
| Correctness | Same oracle states, device effects, final frame and return |
| Code/data | Assembled bytes by owned routine/data class, useful data and padding |
| Resources | Zero page, SFA/static RAM, hardware-stack peak and resident intervals |
| Traffic | Relevant RAM/MMIO reads and writes, including count/order |
| Cycles | Identical named update paths and complete realistic trace total |

Generated output worse than the expert floor fails RD-03. A genuine meet-only result may pass only
with the project-mandated GitHub issue stating the measured gap and concrete compiler change needed
to beat it. A win is recorded directly. RD-03 adds no optional optimizer to improve the comparison;
the full ledger becomes the RD-08 baseline (AR-C13).

## Real ACME and VICE Journey

The qualification builds `examples/m1` through the public compiler service and assembles with real
ACME 0.97. It validates the exact eight-file generation, PRG header/body, startup bytes, labels,
layout, sprite bytes and sidecar cross-hashes before starting VICE (AR-C8, AR-C12).

The real VICE 3.10 case is sequential and local:

1. pin the just-published generation and launch its PRG with the selected PAL profile;
2. stop at the compiler-emitted post-frame-wait/pre-sample label;
3. send the next fixed active-low joystick-port-2 value through binary-monitor command `0xa2`,
   port `1`, then resume;
4. at observation labels, read program state, VIC registers, screen pointer bytes and resident
   sprite bytes, and take indexed-VIC display images for deterministic signatures;
5. compare every observation with the precomputed oracle without changing program memory;
6. observe the complete win, fire release/new press, restored owned state and entry into the pinned
   BASIC return path; and
7. stop VICE externally, close monitor resources and release the exact pin.

The driver never adapts the trace from program state and never writes game variables, branches,
alive flags or expected VIC state. Missing ACME/VICE evidence is `Unknown`, not pass. The accepted
status is `VICE-verified / hardware-unverified` (AR-C11, AR-C12).

## Transition Evidence

The M1 run is not the only proof. Directed cases separately inspect every transition:

| Boundary | Required observation |
|---|---|
| Frontend → semantic CFG | Typed operations, evaluation order, explicit edges and source provenance |
| CFG → whole program | Roots, call/effect closure, initializer order and recursion rejection |
| Whole program → SFA | Complete requests, interference, homes, nested-call staging and certificate |
| SFA → machine | Legal operations, clobbers, volatile count/order, costs and no new storage |
| Machine → layout | Final addresses, visibility, alignment, non-overlap and branch repair |
| Layout → ACME/PRG | Stable text, report/symbol agreement and exact assembled bytes |
| PRG → VICE | Startup, frame behavior, display state, restoration and BASIC return |

Each case states what the next boundary may consume and rejects target facts appearing upstream or
semantic/storage decisions appearing downstream (AR-C3–AR-C8).

## Closeout Evidence

RD-03 execution records:

- ACME/VICE versions and hashes, selected profile and expert-skill identity;
- exact oracle/trace/asset/expert-twin hashes;
- complete behavior, output-cost and host-observation results;
- early C64U seam review with no speculative C64U implementation;
- Linux qualification plus the bounded native-Windows AR-C16 handoff;
- `VICE-verified / hardware-unverified`; and
- the mandatory deferral-expiry review across ambiguity registers, Won't Have sections,
  `spec/future-considerations.md` and the expressiveness ledger.

Host durations and peak memory are observations only. No threshold or performance framework is
introduced. RD-03 formal closeout remains bounded until AR-C16 is discharged at RD-10, while the
Linux compiler result may unlock RD-04 through RD-09 as approved.
