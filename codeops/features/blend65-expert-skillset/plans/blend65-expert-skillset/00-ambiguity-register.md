A correctly typed `word` loop may still lower to an 8-bit machine wrap idiom when range, liveness, and observation proof preserves every source value; a 500-element traversal necessarily retains enough state to distinguish elements above 255. | Accepted 2026-09-07 after clarification. Intentional modular byte behavior is an explicit non-error case; only a provably finite-looking but unreachable termination is rejected. This issue was found proactively from the 300+ element scenario and the modern-developer directive, not supplied as a separate user edge case. | ✅ Product ruling resolved; specification and qualification reconciliation may proceed |
| AR-P39 | Stable introspection width | Does `sizeof(Type)` return `byte` when the computed size is at most 255 and `word` above that boundary, or one stable type for every valid type size? | **Resolved recommendation:** `sizeof(Type)` always has semantic type `word`, just like `length()`. The value remains a compile-time constant, and proof may select byte-only machine work for a consumer, but the computed storage size must not change the arithmetic type of surrounding source. AR-P40 applies the same stable-width principle to `offsetof()`. | Resolved 2026-09-07 under the accepted modern-developer and proactive representation-leak directives. The final Q-L19 review found the old value-dependent rule as the same class of hidden byte/word boundary the user required the skill to discover without prompting. | ✅ Product rule resolved; reconciled as SC-138 and SC-144 |
| AR-P40 | Aggregate query totality and representable fixed-object domain | What type does `offsetof()` have when a field begins after byte 255, what array extents and aggregate sizes can the 16-bit machine model represent, and is `sizeof(T[])` meaningful when `T[]` has no standalone extent? | **Resolved recommendation:** `sizeof(Type)` and `offsetof(Struct, field)` always have semantic type `word` and fold at compile time; proof may narrow machine work but never their source type. Evaluate every array extent and complete nested array/struct size at full precision. Extents must be integers in `0..65535` (E10264), and every fixed array/struct type must occupy `0..65535` bytes (E10265). `sizeof(T[])` is E10266 because unsized arrays exist only as initializer placeholders and any-size parameters, not fixed-size standalone values. This is a 16-bit address/count limit, not a 255-byte struct limit, and adds no runtime. | Resolved 2026-09-07 during final independent correctness review. A valid `struct Big { pad: byte[300]; tail: byte; }` proved the prior byte-return claim false. Artificially capping structs at 255 would be a compiler-convenience restriction and violate modern ergonomics; stable word queries plus the target's full addressable domain are the only viable contract. | ✅ Product rule resolved; reconciled as SC-144/HLE-009 |
| AR-P41 | Index-context operator set | Does direct subscript promotion cover only additive/multiplicative arithmetic, or every integer-producing operator such as shifts, bitwise operators, and unary complement? | **Resolved recommendation:** before any unbarriered integer-producing operation directly inside `[]`, promote `byte` to `word` and `sbyte` to `sword`. The set is unary `~` and `-`, plus `+`, `-`, `*`, `/`, `%`, `<<`, `>>`, `&`, `|`, and `^`; existing rules still reject unsigned unary minus. Comparisons and logical operators yield `boolean` and remain invalid indices. Explicit 8-bit casts, typed 8-bit assignment/compound assignment, and already-completed calls are narrow barriers. This makes `arr[i << 1]` with byte `i == 255` select ordinal 510, while `arr[byte(i << 1)]` deliberately selects 254. | Resolved 2026-09-07 during final independent correctness review. The accepted AR-P37 said “unbarriered operator,” but derived copies disagreed on whether shifts/bitwise operations were included. Covering the complete integer-producing set follows the same modern-developer principle as `i + 10` and avoids another hidden width boundary. | ✅ Product rule resolved; reconciled as SC-145 |

> **AR-P36 supersession:** AR-P36 is resolved. No slice/span/view value survives, and AR-P37 and

### Resolution Notes

**AR-1:** The skillset is a prerequisite and governance capability for compiler recovery, not an asm-parity implementation slice. It receives its own feature lifecycle and plan.

**AR-2:** One public router preserves a single versioned expertise baseline and prevents partial activation; modular reference documents keep the knowledge maintainable and selectively loadable.

**AR-3:** Future machines constrain seam design but do not receive superficial pseudo-expertise in this baseline. Their own deep platform modules are later, separately qualified additions.

**AR-4:** SFA governs all function-execution storage and reaches a final closure over parameters,
returns, locals, temporaries, spills, and function/helper scratch. The 6502 hardware stack remains
available for `JSR`/`RTS`, interrupt state, register preservation, and explicit stack operations;
that does not reopen general dynamic frames. Global data, assets, platform alignment/banking,
segments, loaders, and artifact placement stay outside SFA.

**AR-5:** Current compiler files may be read as evidence while authoring and qualifying the skill, but this plan will not repair or redesign compiler implementation.

**AR-6:** The implementation must prefer small Markdown knowledge modules and validation artifacts over new runtime services, orchestration layers, or generalized support infrastructure.

**AR-7:** Freeze v1.0.0 when compiler recovery starts. Any substantive later skill change—not only
a critical erratum—bumps the single active version by at least a patch, qualifies before atomic
activation, and triggers review only for decisions/artifacts dependent on changed rules. Release
bookkeeping that binds an already-qualified commit is not a substantive change.

**AR-8:** The knowledge modules distill actionable rules and attach claim-level citations to a source manifest pinned by title, edition/revision, URL, retrieval date, and dependent section. Publicly available full manuals remain valid source material, and exact tables may be reproduced locally when useful. Whole-manual embedding is rejected for retrieval noise and poor selective loading, not as a copyright-driven restriction.

**AR-9:** The frozen release must pass all three gates. Qualification uses committed Markdown cases
and result records rather than a new framework. Fresh evaluators operate from an ephemeral
allowlisted copy without expected answers, qualification files, author history, or prior results;
separate graders receive the oracle and captured output.

strengthens AR-24 without adding a new runtime reference, case file, tool, or framework.
