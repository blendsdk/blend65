### Resolution Notes

**AR-1:** The 7a/7b boundary in option B is *addressing-mode-shaped*, not type-shaped: 7a is
everything reachable with direct addressing (abs / abs,X with a byte index), 7b is everything
requiring a ZP pointer + `(ptr),Y` (by-ref params, tier-2 arrays, unsized params). That keeps
`load_indirect`/`store_indirect` and the ZP-pointer allocation story in ONE plan instead of half
in each. Aggregate returns are rejected in 7a with their permanent spec codes (E10093/E10120 —
returns are illegal forever, not deferred); aggregate PARAMS are rejected with a loud
temporarily-unsupported diagnostic until 7b (5b call-bearing-init precedent).

**AR-2:** `parseStructLiteral` (FR-45, `pratt.ts:335`) is the template: literal allowed where
`allowStructLiteral` is true; `[` in `parsePrimary` gated the same way. Element exprs parsed with
the normal expression parser; the `;` fill separator (if AR-3 ships it) parsed inside the literal.

**AR-6:** Whatever the choice, the evaluator must stay bounded on adversarial input (RD-18
Security Considerations): memoisation + in-progress marks give linear work and loud cycles.

**AR-13:** The registry's own comment (`diagnostic-codes.ts:244`) acknowledges "E10230–E10236 are
the frozen enum codes", so registering E10230 for non-const member values follows the file's own
account of the band. The unified recursive-struct mint mirrors unified recursion E10174 (a
self-reference is a 1-cycle); Ch 07's E10091/E10092 split would spend two numbers on one check.

**AR-15:** Under option A no new IL op semantics are invented: `load_indexed(base, index)` means
`byte at base+index`, translate emits `LDX index; LDA base,X` (tier 1). Scaling is ordinary IL
arithmetic upstream, visible to Phase-B optimizers.

**AR-16:** The result is a compile-time constant in every legal position (all three fold), so
value-dependent typing costs nothing at runtime and matches how numeric literals already type.
