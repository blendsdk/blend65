## Overview

`@blend65/cli` wraps the facade: parse argv (yargs@17 — AR-V1), dispatch to
`build`/`compile`/`emitAsm`/`emitIl`, render results (diagnostics → stderr,
summary/report → stdout), write emit-flag artifacts, classify the exit code (R50).
The only compile-path package that prints (R4/AC-18).

## Module Layout (AR-V9)

| File | Responsibility |
| ---- | -------------- |
| `src/bin.ts` | `#!/usr/bin/env node`; `runCli(hideBin(process.argv), realIo).then(c => { process.exitCode = c; })` (AR-V13) |
| `src/main.ts` | `runCli(argv: string[], io: CliIo): Promise<number>` — the testable entry; dispatch + exit classification |
| `src/args.ts` | All yargs configuration; exports `parseArgs(argv, onFail)` returning a clean `ParsedArgs` (isolates yargs typing friction) |
| `src/render.ts` | Output orchestration: diagnostics, trailer, summary table, JSON report, artifact writes for `--emit-*` |
| `src/color.ts` | `resolveColor(flag: boolean | undefined, env, isTTY): boolean` (AR-V2/V16) + local SGR accent helpers (same pattern as `core/src/diagnostics/ansi.ts`) |
| `src/index.ts` | Exports `runCli`, `CliIo`, `VERSION` |

```typescript

export interface CliIo {

```

## Argument Parsing (`args.ts`)

The RD §4.3 sketch is the normative flag table (R15–R36, R45–R46), with these pinned
mechanics:

- Commands: `.command(['$0 [files..]', 'build [files..]'], …)` (AR-V14) and
  `check [files..]` (R18). `.strict()`, `.help()` (R32), `.version(VERSION)` (AR-V15).
- `--warn-as-error`: `{ type: 'string', array: true }`; bare occurrence parses as `""`
  → coerced to `true`; code-valued occurrences accumulate (R26/R27, PF-009 sketch).
- `--color`: `{ type: 'boolean', default: undefined }` so explicitness is detectable
  (AR-V16); yargs boolean-negation gives `--no-color` → `false` (R35).
- `--report`: `{ choices: ['json'] }` (R36); `--diagnostics-format`:
  `{ choices: ['terminal', 'json'], default: undefined }` — undefined so the config
  value survives merging (RD-16 R24: only *set* flags override).
  Same for every flag with a config counterpart (`out-dir`, `out-name`, `optimize`,
  `quiet`, `max-errors`, `startup`): **no yargs defaults** — defaults live in
  `CONFIG_DEFAULTS` (RD-16 R24); a yargs default would masquerade as an explicit
  override. (The RD §4.3 sketch's `default:` annotations document effective defaults;
  the merge engine owns them.)
- `.fail((msg) => onFail(msg))` — custom handler (R50 mandates overriding yargs'
  default exit-1): `main.ts` prints `blendc: <msg>` + usage hint to stderr and returns
  **2**. `.exitProcess(false)` so yargs never calls `process.exit` (R11-adjacent:
  the CLI owns its lifecycle, AR-V13).

`ParsedArgs → CompilerOptions` mapping: `files..` → `sourceFiles` (tier 1);
`--config` → `configPath` (R45); `io.cwd` → `options.cwd` (PF-002/AR-V20 — the base dir
for config discovery + relative-path resolution); all others 1:1 (R9).

- **Help/version/`.fail()` output routing (PF-009):** with `.exitProcess(false)` yargs
  writes help, version, and error text through its *own* console binding, not `CliIo`.
  `parseArgs` therefore uses the parse-callback form
  (`yargs(...).parse(argv, (err, argv, output) => …)`) and returns `output` so `main.ts`
  routes it through `CliIo` — help/version → `writeOut`, `.fail()`/usage errors →
  `writeErr`. Without this, ST-35's fakeIo cannot capture `--version`/`--help`.

## Dispatch (`main.ts`)

| Invocation | Facade call | Notes |
| ---------- | ----------- | ----- |
| `build` + `--emit-il` | `emitIl(options, host)` | Write `<outDir>/<outName>.il`, exit by diagnostics (R23) |
| `build` + `--emit-asm` | `emitAsm(options, host)` | Write `<outDir>/<outName>.asm` (CLI-side write, R22 "uses emitAsm()") |
| `build` (default) | `build(options, undefined, io.buildDeps)` | Full pipeline (R17) |
| `check` | `compile(options)` | No artifacts, no summary table (R18) |

`--emit-report` (R24): after a successful `build()`, additionally write
`renderReportJson(result.resourceReport)` to `<outDir>/<outName>.report.json`
(§4.4 layout). `outName` for all CLI-side writes (build **and** `emitAsm`/`emitIl`) is
the single facade-derived value from `runFrontend` step 4, surfaced on every result as
the effective `result.config.outName` (R51) — the CLI **never re-derives** it
(PF-001/PF-010).

### Exit-code classification (R50 — normative order)

```
yargs .fail() fired                                → 2
result has any config-band (E10240–E10246) or E10250/E10251 diagnostic
  (equivalently: pipeline aborted before lexing)   → 2
result diagnostics contain any ICE-band code       → 3   (R44; .asm retained)
  (isIceCode(code) — /^E9\d{4}/, core diagnostic-codes.ts)
any error-severity diagnostic in final array       → 1
otherwise                                          → 0   (warnings don't affect it, R41)
```

Implementation detail: R50's classification is derivable from the diagnostic codes
alone (config band E10240–E10246 + E10250/E10251 → 2; any ICE-band code → 3), so no new
result field is added. **Exit 3 keys on the ICE band via the shipped `isIceCode(code)`
helper, not a specific ACME code** (PF-003/AR-V21): there is *no* ACME-specific ICE
code — an ACME assembler failure is reported as the generic `IceCode.Unexpected`
(`E90001`, `invoke-acme.ts:122`), the same code frontend/codegen stages emit, so banding
on `isIceCode` matches R44's "internal compiler error" rationale and stays correct as
ICEs proliferate. **ACME-not-found is `E10035`** (`AcmeNotFound` — a normal error
diagnostic emitted by `discoverAcme`, *not* an ICE), so it falls through to **exit 1**
(R50-literal: an ordinary user-actionable error — PF-003 Decision 2). The R44/R50
wording clarification (exit 3 = ICE band; `E10035` → 1) is logged as AR-V21.

## Rendering (`render.ts`)

Order of output on every run (R38/R39, AC-17, AR-V11):

1. **Diagnostics → stderr.** `diagnosticsFormat === 'json'` → `renderJson(diags)`;
   else `renderTerminal(diags, sourceMap, { color })`. Empty array renders `""`
   (core contract) — nothing written.
2. **Trailer → stderr** (AR-V11): terminal format only; errors>0 →
   `error: <N> error[s][, <M> warning[s]] emitted` (warning clause only when M>0);
   else warnings>0 → `warning: <M> warning[s] emitted`; else nothing. Severity word
   painted bold red/yellow via `color.ts` when color is on (AR-Q9 map). Not
   suppressed by `--quiet` (R34 scope is the summary table).
3. **Build summary → stdout** (R38): only for `build` command, only on success
   (exit code 0), only when `!config.quiet` and `--report` unset:
   `renderReportTerminal(result.resourceReport)` (uncolored by design — RD-11 §4.7).
4. **JSON report → stdout** (R36): `--report=json` → `renderReportJson(report)`
   to stdout regardless of `quiet` (it implies table suppression).

Color resolution (AR-V2/V16, replaces chalk per the ratified amendment):

```
explicit --color        → true
explicit --no-color     → false
env.NO_COLOR defined    → false          (any value, per no-color.org)
io.isTTY                → true
otherwise               → false
```

## Error Handling

| Error Case | Handling Strategy | Source |
| ---------- | ----------------- | ------ |
| Unknown flag / bad choice value / unknown command | `.fail()` → stderr message + exit 2 | R50, AR-V13 |
| Config-band diagnostics | Config diagnostics carry `CONFIG_SOURCE_ID = -2` spans, which `SourceMap.has()` rejects (id ≥ 0 required) → **header-only degradation** (no `--> file:line:col`) for v1 — accepted, logged AR-V22; the AR-P2 `sourceId` seam (`config/src/validate.ts:47`) is the follow-up. Exit 2 | R43, R50, R51, PF-008 |
| Driver-band diagnostics (E10250/E10251) | Null span by design (no source to point into) → header-only per R51; exit 2 | R48/R49, R51 |
| ACME ICE | Diagnostics rendered; `.asm` path noted in the ICE message (RD-09 behavior); exit 3 | R44 |
| Artifact write failure (`--emit-*` CLI-side writes) | `blendc: <message>` to stderr, exit 2 (invocation-class: bad `--out-dir`) | Design (AR-V9 render.ts owns writes) |
| `--quiet` + errors | Diagnostics + trailer still print (quiet touches only the table) | R34, AR-V11 |

## Testing Requirements

- Spec: ST-22..ST-38 — all via in-process `runCli(argv, fakeIo)` with fake `BuildDeps`
  (AR-V4); plus ST-40 real-ACME E2E (skipIf-guarded).
- Impl: flag-mapping table (each flag → `CompilerOptions` key), trailer pluralization
  matrix, color matrix (flag/env/TTY combinations beyond the spec cases), `--emit-report`
  without build success, artifact-write failure path.
- Security: no shell involvement (argv arrays end-to-end); path arguments resolved and
  written only under `--out-dir` (existing `emitBinary` behavior; CLI-side writes join
  `outDir` + derived basename — no user-controlled traversal in the basename since the
  extension is stripped and `basename()` is applied).
