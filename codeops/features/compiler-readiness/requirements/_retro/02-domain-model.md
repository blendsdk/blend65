# Domain Model: Blend65 Compiler Readiness

> Generated by retro-requirements — Phase 2: Data Model Extraction · Date: 2026-07-23

## Entity Inventory

| Entity | Description | Key relationships |
|---|---|---|
| Specification rule | Normative statement governing syntax, semantics or diagnostics | Owns generated cases and expected outcomes |
| Source program | One or more Blend65 modules plus a target profile | Is accepted or rejected; may produce an artifact |
| Semantic model | Typed, resolved interpretation of the program | Feeds allocation and lowering |
| Diagnostic | Stable code, severity, source span and explanation | Explains rejected or risky programs |
| IL program | Target-independent executable meaning | Must preserve source semantics |
| Instruction stream | Target-specific operations and symbols | Must preserve IL semantics |
| Build artifact | Assembly, binary, labels and reports | May be executed by a target oracle |
| Observable outcome | Memory, termination, diagnostics or artifact status | Compared with an independent expected outcome |
| Generated case | Seeded program plus traceable rule coverage | Reproducible and shrinkable |
| Readiness claim | Status of a rule/capability for a target and configuration | Supported only by passing evidence |

                                        ↓

                                        │                    │

## Invariants

- A readiness claim is invalid unless it names the specification rule, target, generator version,
  seed/case identity and oracle.
- A generated valid case must have a defined semantic outcome before compilation begins.
- A generated invalid case must name the expected diagnostic family and emission consequence.
- Undefined or ambiguous specification behavior cannot contribute to a pass rate.
- Performance evidence cannot turn an incorrect or unsupported semantic case into a pass.
- A minimized failing case retains the same rule coverage and failure classification.

## Finite Value Sets

| Set | Values |
|---|---|
| Case class | valid, invalid, ambiguous-excluded |
| Result class | pass, semantic mismatch, diagnostic mismatch, ICE, assembler failure, timeout |
| Evidence tier | frontend, lowering, assembly, emulator |
| Confidence | confirmed, inferred, suspicious |
| Readiness status | unmodeled, modeled-failing, modeled-passing, explicitly unsupported |
