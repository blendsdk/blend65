> Generated by retro-requirements — Phase 3: API & Interface Surface · Date: 2026-07-23

## Public Surfaces

| Surface | Inputs | Outputs | Readiness relevance |
|---|---|---|---|
| Compiler API | sources, target/configuration | diagnostics, assembly, build results | Primary automation boundary |
| `blendc` CLI | files, platform and output flags | exit status, diagnostics, artifacts | User-visible contract |
| Language server | document text and editor requests | diagnostics and language data | Must agree with frontend semantics |
| Generated-case runner | rule model, target, seed | classified reproducible outcome | Proposed readiness authority |
| ACME invocation | emitted assembly | PRG/labels or assembler errors | Target legality boundary |
| VICE harness | executable, setup and observation window | memory/register/termination evidence | Runtime semantic boundary |

## Required Generated-Baseline Interface

The reconstructed need is a deterministic tool surface capable of:

1. Selecting specification rules and type/value domains.
2. Generating valid and invalid programs from a recorded seed.
3. Computing expected results without importing compiler implementation logic.
4. Compiling through public APIs.
5. Optionally assembling and executing on the selected platform.
6. Classifying, persisting, replaying and minimizing failures.
7. Producing a rule-by-rule readiness matrix rather than one aggregate score.

No HTTP, authentication or multi-user API exists in this project.
