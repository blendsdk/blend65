# Cross-Cutting Concerns: Blend65 Compiler Readiness

> Generated by retro-requirements — Phase 6: Cross-Cutting Concerns · Date: 2026-07-23

## Error Handling

Diagnostics have stable codes and spans across frontend and compiler surfaces. Recovery exists for
many invalid inputs, but the absence of a generated no-ICE campaign means robustness is not
demonstrated over the legal and malformed input spaces.

## Determinism and Reproducibility

The repository uses committed fixtures and goldens. A generative baseline additionally needs
recorded generator version, seed, target, configuration and minimized reproducer for every failure.

## Configuration

Compilation depends on source files, target/platform configuration and output paths. No `.env`
configuration or hosted service is involved.

## Security

This is a local compiler, not an authenticated network service. Relevant security properties are:

- never interpolate untrusted paths into shell commands;
- canonicalize staged paths and reject traversal;
- bound generated input size and emulator execution time;
- isolate temporary artifacts;
- treat malformed source as data, never executable host code;
- avoid leaking arbitrary host files through compiler diagnostics or embeds.

## Testing Strategy Observed

| Tier | Strength | Current limitation |
|---|---|---|
| Specification tests | Pin named intended behavior | Coverage is manually selected |
| Implementation tests | Exercise internal shapes and edges | Can preserve an accidental architecture |
| Golden assembly | Detects emitted-text drift | Previous output is not semantic truth |
| ACME assembly | Proves target syntax legality | Legal assembly may still be wrong |
| VICE tests | Prove selected runtime observations | Sparse and example-specific |
| Twin scoreboard | Exposes code-quality differences | Corpus-dependent; static-cycle aggregate |

## Required Cross-Cutting Baseline Properties

- Deterministic generation and replay.
- Independent expected-value computation.
- Bounded execution and timeout classification.
- Failure shrinking.
- Rule and combination coverage reporting.
- Mutation checks proving that important oracles can fail.
- Versioned exclusion records for ambiguous or unsupported specification rules.
