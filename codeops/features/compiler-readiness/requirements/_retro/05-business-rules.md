## Readiness Rules Reconstructed from the User Goal

These are goal constraints supplied in this conversation, not observations promoted from code:

- Compiler readiness is evaluated against the language specification.
- `boing-ball` is not an authoritative baseline because it was authored under the same compiler
  limitations being assessed.
- Existing asm-parity work must be classified rather than silently discarded or treated as the
  destination.
- A generative baseline must not reproduce compiler behavior as its semantic oracle.
