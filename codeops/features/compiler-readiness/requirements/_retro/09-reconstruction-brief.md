## Project Identity

Blend65 is a statically typed systems language and AOT compiler for 6502 platforms. Its intended
user writes modern, expressive source without needing assembly lore; its generated code must be
correct on target hardware before optimization quality is considered.

The compiler-readiness feature must establish, from the frozen v3.0 language specification,
whether mandatory language behavior is implemented correctly, rejected correctly, robust against
malformed input, and executable on the target. It replaces compiler-authored examples and
assembly-parity ratios as the authority for readiness.

## Business Rules

| ID | Rule | Confidence |
|---|---|---|
| BR-01 | No mandatory rule contributes a pass until it has a machine-readable model and oracle | ✅ |
| BR-02 | Undefined or ambiguous behavior is excluded visibly and requires an errata ruling | ✅ |
| BR-03 | Valid cases compare observable semantics; emitted assembly text is not semantic truth | ✅ |
| BR-04 | Invalid cases compare diagnostics and must not emit an executable | ✅ |

| BR-09 | A readiness release has zero unexplained mandatory-rule exclusions | ✅ |

## Workflow

1. Import a normative specification rule into the inventory.
2. Resolve ambiguities through the errata process.
3. Define valid/invalid generation domains and independent expected outcomes.
4. Generate deterministic cases from bounded seeds.
5. Run the cheapest sufficient tier, escalating valid executable cases through ACME and VICE.
6. Classify mismatches and shrink failures.
7. Update the readiness matrix without changing the rule model to excuse compiler behavior.
8. Feed confirmed gaps into the recovery roadmap.
9. Run secondary example, twin and performance suites only after semantic gates pass.

## Cross-Cutting Requirements

- Deterministic generation, replay and shrinking.
- Strict separation between rule model, reference semantics and compiler implementation.
- Bounded program size, compile duration and emulator execution.
- Safe temporary paths and subprocess invocation.
- Human-readable and machine-readable readiness reports.
- Stable failure classes and no silent skips.
- Generator/oracle mutation checks.

## Known Gaps and Improvement Opportunities

| Gap | Direction |
|---|---|
| Runtime/computed memory intrinsic addresses rejected | Highest-priority conformance recovery |
| Const-foldable nonliteral addresses rejected | Cover within the same rule family |
| Remaining silent-miscompile and IRQ work | Complete before broad optimization |
| No spec-wide coverage denominator | Build inventory first |
| No independent semantic evaluator | Start with a deliberately bounded pure subset |
| Static cost confused with runtime measurement | Rename before reuse |
| Sparse VICE rule coverage | Add generated observable-memory programs |

## Explicitly Excluded from Readiness

- Universal hand-assembly byte/cycle parity.
- Whole-program “beat expert” claims.
- Compiler-authored demos as representative authority.
- Assembly goldens as semantic proof.
- A single aggregate readiness percentage without its rule matrix.
