# ACME Labels & PRG Binary Analysis

> **Document**: 03-acme-labels-prg-analysis.md
> **Parent**: [Index](00-index.md)

## Overview

This component adds two critical capabilities to `diag_app.sh`:
1. **ACME label file generation** — Extract all symbol addresses from the assembled binary
2. **PRG binary validation** — Verify the binary structure is valid for C64 execution

These are the simplest and highest-impact improvements, requiring minimal code changes.

## Architecture

### Current ACME Invocation

```bash
$ACME_BIN $ACME_FLAGS -o "$PRG_FILE" "$ASM_FILE" > "$ACME_LOG" 2>&1
# Where ACME_FLAGS="--cpu 6510 --format cbm"
```

### Proposed ACME Invocation

```bash
LABELS_FILE="$LEVEL_DIR/output.labels"
$ACME_BIN $ACME_FLAGS -l "$LABELS_FILE" -o "$PRG_FILE" "$ASM_FILE" > "$ACME_LOG" 2>&1
```

## Implementation Details

### 1. ACME Label File Generation

**Change:** Add `-l output.labels` to every ACME invocation in `diag_app.sh`.

**ACME label file format:**

```
; generated by ACME
__armenianFont = $1000
__helloWorld = $0900
__snakeX = $0920
__snakeY = $0946
main = $0860
plotChar = $0830
clearScreen = $0840
copyCharset = $0850
delay = $0855
__basic_stub = $0801
```

**Label Analysis (new Step 6a in `diag_app.sh`):**

After ACME assembly, analyze the label file:

```bash
# Extract and display label addresses
echo "Label Addresses:"
grep -v "^;" "$LABELS_FILE" | sort -t= -k2 | while read line; do
  echo "  $line"
done
```

**Automated checks on labels:**

| Check | Description | How |
|-------|-------------|-----|
| **@charset alignment** | Labels for @charset data must be 2048-byte aligned | `addr & 0x7FF == 0` |
| **@data placement** | Data labels should not overlap with code | Compare code vs data address ranges |
| **Address range** | All labels should be in valid C64 RAM ($0801-$CFFF) | Range check |
| **No collisions** | No two segments should overlap | Sort by address, check gaps |

**Implementation — Label validation function:**

```bash
# validate_labels() — Check label addresses for common issues
validate_labels() {
  local labels_file="$1"
  local level="$2"
  local warnings=0

  # Parse labels (skip comments)
  while IFS='=' read -r name addr; do
    [[ "$name" =~ ^[[:space:]]*\; ]] && continue
    [[ -z "$name" ]] && continue

    name=$(echo "$name" | tr -d ' ')
    addr=$(echo "$addr" | tr -d ' $')
    addr_dec=$((16#$addr))

    # Check @charset alignment (2048-byte boundary)
    if [[ "$name" == *"Font"* || "$name" == *"charset"* ]]; then
      if (( addr_dec % 2048 != 0 )); then
        warn "$level: @charset '$name' at \$$addr is NOT 2048-byte aligned!"
        ((warnings++))
      fi
    fi

    # Check address is in valid C64 user RAM range
    if (( addr_dec < 0x0801 || addr_dec > 0xCFFF )); then
      if [[ "$name" != "__basic"* ]]; then
        warn "$level: Label '$name' at \$$addr is outside user RAM range"
        ((warnings++))
      fi
    fi
  done < "$labels_file"

  return $warnings
}
```

### 2. PRG Binary Validation

**New Step 6b in `diag_app.sh`:**

Validate the assembled PRG binary structure.

**C64 PRG Format:**

```
Offset  Size  Content
------  ----  -------
$0000   2     Load address (little-endian, should be $01 $08 = $0801)
$0002   ...   Program data starting at load address
```

**BASIC Stub (at $0801 in memory):**

```
$0801: next-line-ptr-lo  next-line-ptr-hi  line-number-lo  line-number-hi
       $9E  ASCII-digits-of-SYS-address  $00  $00  $00
```

- `$9E` = BASIC token for `SYS`
- ASCII digits = address of machine code entry point
- The `SYS` address should point to valid code after the BASIC stub

**Implementation — PRG validation function:**

```bash
# validate_prg() — Check PRG binary structure
validate_prg() {
  local prg_file="$1"
  local level="$2"
  local warnings=0

  # Check minimum size (at least load address + minimal BASIC stub)
  local prg_size=$(wc -c < "$prg_file" | tr -d ' ')
  if (( prg_size < 15 )); then
    fail "$level: PRG too small ($prg_size bytes) — likely corrupted"
    return 1
  fi

  # Check load address (first 2 bytes = $01 $08 for $0801)
  local load_lo=$(xxd -p -l 1 -s 0 "$prg_file")
  local load_hi=$(xxd -p -l 1 -s 1 "$prg_file")

  if [[ "$load_lo" != "01" || "$load_hi" != "08" ]]; then
    fail "$level: PRG load address is \$${load_hi}${load_lo}, expected \$0801"
    ((warnings++))
  else
    ok "$level: PRG load address ✓ (\$0801)"
  fi

  # Check BASIC stub — look for $9E (SYS token) in first 20 bytes
  local basic_bytes=$(xxd -p -l 20 -s 2 "$prg_file")
  if [[ "$basic_bytes" == *"9e"* ]]; then
    # Extract SYS address from ASCII digits after $9E token
    ok "$level: BASIC SYS stub found ✓"
  else
    fail "$level: No BASIC SYS stub found — program won't autostart!"
    ((warnings++))
  fi

  return $warnings
}
```

## Integration Points

- Modifies existing `diag_app.sh` Step 3 (ACME invocation) and adds new Steps 6a-6b
- Label files are consumed by VICE integration (`diag_vice.sh`) for address-based memory checks
- PRG validation results feed into the summary report

## Error Handling

| Error Case | Handling Strategy |
|------------|-------------------|
| ACME fails to generate label file | Warn but continue — labels are diagnostic, not critical |
| Label file is empty | Warn — likely no labels in assembly |
| PRG file too small | Error — assembly likely failed silently |
| `xxd` not available | Fall back to `od` or skip binary analysis with warning |

## Testing Requirements

- Verify label file is generated for each optimization level
- Verify label validation catches misaligned @charset data
- Verify PRG validation catches incorrect load addresses
- Verify PRG validation detects missing BASIC stubs
- Test with known-good PRG (border-cycle) and potentially broken PRG (armenian-charset)
