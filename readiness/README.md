# Compiler-readiness artifacts

The JSON inventory under `inventory/` is loose authoring authority. The identity ledger is
append-only, and the review files record independent semantic approval against reproducible
digests. Files under `generated/` and the declaration module in
`packages/readiness/src/generated/` are loose derived projections. A readiness claim is made only
through the digest-verified publication selected by the atomic pointer under
`readiness/publications/`.

From the repository root:

- `yarn readiness:source-check` validates that both loose projections match the authoring
  inventory without writing any file.
- `yarn readiness:generate` explicitly regenerates both projections while holding the
  PID/token-owned publication lock.
- `yarn readiness:publish` validates the package-owned fresh candidate catalog and independently
  authored staged semantic review, builds and accepts one immutable release, then atomically
  selects it.
- `yarn readiness:check` resolves the selected pointer and validates every manifest member,
  digest, binding and opaque snapshot capability without writing.

Generation renders both outputs from one inventory read before publishing them. Each output embeds
the same generation digest, allowing check mode to detect a stale or mixed pair after an interrupted
publication. Loose inventory, identity, and review-evidence files are never generated by these
commands. Publication preparation emits a digest-bound review request but never manufactures
acceptance; the pointer is changed only by the guarded publish transaction.

The selected release currently contains nine bindings: the four deterministic generation
capabilities from the original publication plus four independent result oracles and
`transform.semantic-relations`. Compatible additions are staged against a genuine named base,
independently reviewed, fully resolved before commit, and then selected through a single-use
incremental capability. Readers resolve one complete old or new snapshot; they never assemble
bindings from loose files. Named historical releases remain resolvable after selection advances.
